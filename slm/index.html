The journey

Step 01

Text becomes tokens

Tokenization "digitises" language: words have to become numbers before they can go through all the matrix multiplications. The main design choice is where to draw the line between characters and words. BPE finds common chunks and forms a middle ground.

In my words

Sharpened: IDs are labels, not quantities. Token 39 isn't "near" token 40, any more than locker 39 is. It also runs both ways: the model reads and writes IDs, and decoding turns them back into text.

Step 02

Tokens become vectors

We can't use token IDs directly because they imply false relationships: if ING is 39 and A is 40, they look close on the number line but aren't. Instead each token gets a vector, a row in a matrix, which starts random and is learned in training. The vector size is a training parameter: bigger captures more nuance but needs more parameters; smaller is easier to train but loses information. It gives us a vector database of tokens, I guess, and relationships between them.

In my words

Sharpened: vector size is a hyperparameter, fixed before training. The parameters are the numbers in the table, which training adjusts. And it's a lookup table inside the model, not a database: token 39 means "take row 39".

Step 03

The whole job: predict the next token

The model outputs a probability distribution over all tokens. You'd pick the max, or maybe use some epsilon strategy so you don't always take the top one. It actually outputs logits, which can be anything, and softmax squashes them between 0 and 1 so they sum to 1. The nice part is you train on the text itself: in "to be or not to be", T should be followed by O, O by a space, and so on. You get lots of training from each sentence, with no labelling or grammar rules, unlike the NLP I did at university.

In my words

Sharpened: each example is "given everything so far, what's next?", not "T is followed by o". The input grows at every position: T→o, To→·, To·→b. Using that whole prefix well is what separates a dumb model from a smart one. And my epsilon hunch has a name: sampling from the distribution (Step 08).

Step 04

The simplest possible model

A bigram model predicts the second token from the first. With 65 tokens that's a 65 × 65 lookup table of co-occurrence counts. Or a neural net with random values, trained with gradient descent and Adam. Either way there's no memory or attention.

In my words

Claude pushed back That's the what, not the why. If counting works, why use a net? Try predicting from the last 10 characters instead of 1.

That'd be a 10-dimensional grid, 65 × 65 × 65 and so on. Absolutely massive.

Claude nudged Size is one problem. The other is that almost every cell would be empty. How does a net cope? Think back to Step 02.

Its embeddings learn which characters are similar. So even with sparse data it can say: A is close to E, they're both vowels, so both come between consonants.

In my words

Sharpened: generation samples from the row instead of always taking the top character, which gets stuck in loops. And the two versions really do converge: counting scores a loss of 2.455, the trained table 2.459.

Step 05

Measuring wrongness, then fixing it

Loss measures the gap between a probability of 1 for the right answer and the probability the model actually gave it. If it gave the space after "to" a probability of 0.001, loss is −log(0.001) = 6.9. We use log because it scales up exponentially (I think) the more wrong you are. Backprop gives the gradient, the slope towards zero loss, and step size is a hyperparameter. Then mini-batches for speed, Adam, and train/test splits plus a holdout set, as in standard ML.

In my words

Sharpened: the log isn't exponential, it's unbounded. Every 10× drop in probability adds the same 2.3, all the way to infinity, so a confident mistake can't hide. And the gradient doesn't point at zero loss. It's the local slope under your feet in fog, one number per parameter, so we take thousands of small steps and re-measure each time.

Step 06

Letting tokens look at each other

Attention is a smart way to use the context before a token. Averaging it gives a murky blob; instead we learn which tokens should attend to each other. Each token gets three vectors, Q, K and V, from learned weights WQ, WK, WV. Q is what I'm looking for, K is what I offer, V is what I give when attended to. For every earlier token (with a position embedding to keep the order), the dot product of my Q with its K says how well they match, and a weighted sum of the V vectors gives a "context-aware" vector.

In my words

Claude asked Why only earlier tokens? In training the whole sequence goes in at once. What goes wrong if position 5 can see position 6?

You can't predict the next token if you can see it. So we mask to only the tokens that came earlier.

In my words

Sharpened: between the dot products and the weighted sum, the scores go through softmax (Step 03), so each token splits exactly 100% of its attention across the past. Without the mask the model would learn to copy the answer, a skill that's useless at generation time, when there's no future to see.

Step 07

Stacking it into a transformer

This one took a while, and the page shows the confusion.

Stacked transformer blocks take a token embedding and add an attention component and an MLP component. The MLP I'm not sure about: it expands the token through two layers and shrinks it back. Is that just useful learning about the token itself? LayerNorm, I think, keeps the numbers from blowing up across many blocks.

My first attempt

Claude explained Attention only blends; the MLP does the "if this and that" computation. Then it asked about the parts I'd skipped: residual connections and stacking.

… I still don't get the point of the MLP. It takes x, expands it and shrinks it. But what does that vector represent?

Claude reframed it x is each token's notepad: one vector per position that every layer reads and adds to. An MLP neuron is a pattern detector, like a CNN filter. Weights +1, +1, +1 and a bias of −2 under a ReLU fire only for -eak. Averaging can't express "only if all three".

Without attention, the input is an n × 384 matrix with an MLP in each block. Is it one MLP applied to each row, or a separately trained MLP per row? … And WQ, WK, WV are three learned matrices that turn each embedding into its own Q, K and V?

Questions I asked

Claude answered One MLP per block, shared by every row, like one conv filter sliding over an image. And with no attention, no row ever sees another, so the whole stack collapses back into a bigram.

Attention learns relationships between tokens: a weighting over everything before. The MLP learns nonlinear combinations within each token's own vector. A block needs both, because attention only decides how much to weigh the context, not what to output. […] We add to the notepad rather than rewrite it, so one weird layer can't wipe out what earlier layers learned; the combination of layers gives depth and range. Layer 2 has more baked in, so it can learn more.

Where I landed

Sharpened: attention routes, the MLP computes. And "more baked in" is specific: by layer 2, a's notepad already holds notes about its neighbours, so when k reads a it gets two hops of context. Each layer adds a hop.

Step 08

Making it talk

The loop does a full forward pass per character, using a KV cache so it doesn't redo the ones it's already done. The context window slides once we pass the max length. We can't go back and try a different branch once we've committed. Temperature sets how far we stray from greedy. A prompt is just the start of the text.

In my words

Claude nudged A KV cache is an optimisation real systems add, not part of the loop; mine reruns the whole window for every character. Then it asked which way temperature goes, and what top-k is for.

Temp 0 is ice cold, total greed; higher is more random. I don't know why 1 is the "real" distribution. Top-k cuts the long tail in case it derails the whole thing.

Claude answered Dividing by 1 changes nothing, so T = 1 is what training produced: cross-entropy (Step 05) pushed softmax(logits) to match how often each character really follows. Any other temperature is a distortion chosen at generation time.

Sharpened: the long tail is a numbers game. Any one rare character is unlikely, but together they're a few percent per step, over hundreds of steps. In the replay below, the chance of 300 characters with no pick outside the top 10 is tiny. And with no going back, one bad pick stays in the context and steers everything after it.

Where I ended up

Eight steps took me from "words need to become numbers" to a 10.8M-parameter transformer that writes passable fake Shakespeare. Validation loss fell from 4.17 (guessing) to 2.48 (bigram), 2.02 (one attention layer) and 1.46 (the full model). Every gain came from the same idea: let the model use more of its context, and learn which parts matter.

A chatbot is this scaled up: subword tokens, thousands of times more parameters and text, then further training on conversations. The loop underneath doesn't change. Predict the next token, sample, repeat.
